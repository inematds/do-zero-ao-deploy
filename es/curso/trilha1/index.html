1.1 ~45 min

💻 La terminal

La ventana de texto donde conversas directamente con la computadora. Sin menús, sin clics: solo tú y la máquina.

Qué es:

Una ventana de texto donde escribes comandos y la computadora responde. CMD y PowerShell son los de Windows; shell (Bash/Zsh) es el de Mac y Linux; "consola" es solo otro nombre para lo mismo.

Por qué aprender:

Casi todas las herramientas de programación (Git, deploy, servidores) se operan con texto. Aprender a usar la terminal es como aprender a hablar el idioma nativo de la computadora.

Conceptos clave:

Escribes un comando y responde. La señal $ (o > en Windows) significa «estoy esperando que escribas». Todos los nombres apuntan a la misma idea.

Qué es:

El paso para encontrar y abrir el terminal en tu sistema: Windows + R y «cmd» en Windows, Cmd + Espacio y «Terminal» en Mac, Ctrl + Alt + T en Linux.

Por qué aprender:

Sin saber cómo abrirlo, no pasa nada. Cada sistema tiene su manera, pero el resultado es el mismo: una ventana esperando tus comandos.

Conceptos clave:

En Windows, prefiere PowerShell (moderno). En Mac y Linux, Terminal ya viene instalado. Al abrirlo, ves el prompt con tu nombre de usuario.

Qué es:

Los tres comandos de navegación: pwd (dónde estoy), ls (qué hay aquí) y cd (ir a otra carpeta).

Por qué aprender:

En la terminal no ves las carpetas, preguntas por ellas. Estos comandos son tu mapa: sin ellos, te pierdes en cualquier proyecto.

Conceptos clave:

cd .. vuelve una carpeta, cd ~ va a home. Presiona Tab para autocompletar nombres y evitar errores de escritura.

Qué es:

Los comandos para trabajar con archivos: mkdir crea carpeta, touch crea archivo, cp copia, mv mueve/cambia el nombre, rm borra.

Por qué aprender:

Es el "clic derecho > Nueva carpeta" de la terminal, pero más rápido. Puedes crear la estructura de todo un proyecto en segundos.

Conceptos clave:

CUIDADO con rm: borra definitivamente, sin papelera ni Ctrl+Z. Revisa la ruta antes. mkdir -p crea carpetas anidadas de una sola vez.

Qué es:

Dos formas de poner contenido en un archivo: el nano se edita desde la propia terminal; el code abre el archivo o la carpeta en VS Code.

Por qué aprender:

Crear un archivo vacío es solo el comienzo; necesitas escribir en él. Conocer las dos formas te sirve tanto para ediciones rápidas como para proyectos completos.

Conceptos clave:

En nano, ^O guarda y ^X sale (el ^ y la tecla Ctrl). code . abre toda la carpeta actual en VS Code.

Qué es:

Un ejercicio práctico: crear el árbol de carpetas y archivos de un sitio (index.html, style.css, carpeta img, carpeta pages) usando solo el terminal.

Por qué aprender:

La práctica lo integra todo. Cuando montas un proyecto sin salir del terminal, los comandos se vuelven automáticos y ganas confianza.

Conceptos clave:

Combina mkdir + touch + cd. Comprueba el resultado con ls -R. Esta estructura es la base del proyecto de la Trilha 1.

1.2 ~45 min

🌿 Git esencial

Git es un Ctrl+Z infinito para tu código. Cada versión guardada queda almacenada para siempre y ya no perderás trabajo.

Qué es:

Un sistema que guarda fotos (versiones) de tu proyecto a lo largo del tiempo. En cualquier momento puedes ver una versión antigua o volver a ella.

Por qué aprender:

Acaba con el caos de «proyecto-final-2-AGORA-VAI.zip». Experimentas sin miedo, porque toda versión buena queda guardada y nada se pierde.

Conceptos clave:

Cada versión guardada es un «commit» con un mensaje. El historial es una línea de tiempo. Git es la herramienta más usada del mundo para esto.

Qué es:

El paso para descargar e instalar Git en tu computadora: instalador oficial en Windows, brew en Mac, administrador de paquetes en Linux.

Por qué aprender:

Git no viene instalado en todos los sistemas. Instalarlo una vez (y configurar el nombre y el correo electrónico) deja todo listo para el resto del curso.

Conceptos clave:

Revisa con git --version. Configura git config --global user.name e user.email una sola vez.

Qué es:

El flujo para guardar el trabajo: git init inicia Git en la carpeta, git add selecciona qué guardar y git commit guarda la versión con un mensaje.

Por qué aprender:

Es el corazón de Git. Vas a repetir add e commit decenas de veces al día para guardar tu progreso.

Conceptos clave:

add = "prepara"; commit = "guarda definitivamente". El mensaje del commit (-m) explica qué cambió. Haz commits pequeños y frecuentes.

Qué es:

Los comandos de inspección: status muestra qué cambió ahora, log muestra el historial de commits y diff muestra línea por línea lo que se modificó.

Por qué aprender:

Antes de guardar, necesitas ver qué cambió. Estos comandos son tus ojos: evitan que confirmes cambios equivocados por accidente.

Conceptos clave:

Usa git status todo el tiempo. git log --oneline da un resumen claro. git diff muestra el «antes y después».

Qué es:

Las branches son copias paralelas del proyecto. Creas una branch para probar algo nuevo sin tocar la versión principal y luego la unes (merge) si funciona.

Por qué aprender:

Permite experimentar sin miedo: si la idea no funciona, descartas la branch y la versión principal sigue intacta.

Conceptos clave:

git branch nome crea, git checkout (o switch) cambia, git merge junta. main y es la rama principal.

Qué es:

Un archivo de texto llamado .gitignore que indica qué debe ignorar Git: contraseñas, archivos temporales, carpetas pesadas como node_modules.

Por qué aprender:

Sin él, puedes subir contraseñas a Internet o llenar el historial de basura. Es la primera protección de seguridad de todo proyecto.

Conceptos clave:

Una línea por defecto para ignorar. *.log ignora todos los registros; .env protege secretos. Crea el .gitignore antes del primer commit.

1.3 ~45 min

☁️ GitHub y Pages

GitHub es donde vive tu código en la nube: copias de seguridad, colaboración y, con GitHub Pages, tu sitio publicado gratis.

Qué es:

El registro en GitHub, el sitio más grande del mundo para guardar código. La cuenta gratuita ya cubre todo lo que necesitas en este curso.

Por qué aprender:

GitHub es el «portafolio» de quienes programan. Los reclutadores miran tu perfil, y desde ahí se publica tu sitio mediante Pages.

Conceptos clave:

Elige un nombre de usuario profesional (formará parte de la dirección de tu sitio). Confirma el correo electrónico para habilitar todas las funciones.

Qué es:

Un Personal Access Token (PAT) es una contraseña especial que GitHub genera para que el terminal la use en lugar de tu contraseña habitual.

Por qué aprender:

GitHub ya no acepta la contraseña habitual en la terminal. Sin el token, no puedes enviar (push) tu código a la nube.

Conceptos clave:

Genera el token en la configuración de GitHub y cópialo en el momento (solo aparece una vez). Trata el token como una contraseña: nunca lo compartas.

Qué es:

El puente entre tu computadora y GitHub: remote apunta al repositorio en la nube, push envía y pull descarga los cambios.

Por qué aprender:

Es lo que convierte el Git local en una copia de seguridad en línea y colaborativa. Sin el push, tu código nunca sale de tu máquina.

Conceptos clave:

git remote add origin conéctate una vez. git push inicia, git pull baja. origin y es el apodo del repositorio remoto.

Qué es:

GitHub Pages es un servicio gratuito que convierte un repositorio con HTML en un sitio público, con su propia dirección en internet.

Por qué aprender:

Es la forma más sencilla y gratuita de publicar un sitio. En pocos clics, cualquier persona en el mundo puede acceder a tu proyecto.

Conceptos clave:

Actívalo en la configuración del repositorio (pestaña Pages). La dirección queda usuario.github.io/repo. Cada push actualiza el sitio automáticamente.

Qué es:

Asistentes de IA que escriben y completan código por ti dentro del editor: GitHub Copilot y herramientas como Codex.

Por qué aprender:

La IA acelera mucho el trabajo: sugiere comandos, explica errores y escribe fragmentos completos. Quien sabe usarla bien produce más rápido.

Conceptos clave:

La IA sugiere; tú decides y verificas. Describe bien lo que quieres (un prompt claro). Úsala como apoyo, sin dejar de entender qué hace el código.

Qué es:

Un ejercicio que reúne todo: crear un repositorio en GitHub, conectarlo con el proyecto local y enviar (push) el código por primera vez.

Por qué aprender:

Completar el ciclo una vez elimina el miedo. Después de eso, subir cualquier proyecto se vuelve una rutina de pocos comandos.

Conceptos clave:

Secuencia: init → add → commit → remote add → push. Usa el token (PAT) para autenticarte.

🚀 Proyecto: Landing page

La hora de unirlo todo: construyes una landing page desde cero y la publicas en minutos, con dirección propia.

Qué es:

El primer paso del proyecto: crear la carpeta local, activar Git y crear el repositorio correspondiente en GitHub.

Por qué aprender:

Todo proyecto profesional comienza con un repositorio bien configurado. Empezar bien evita tener que rehacer el trabajo más adelante.

Conceptos clave:

Combina lo que viste: mkdir + git init + repositorio en GitHub + remote add. Ten un .gitignore desde el inicio.

Qué es:

HTML es el lenguaje que define la estructura de una página: títulos, párrafos, imágenes y enlaces, organizados en "etiquetas".

Por qué aprender:

Es el esqueleto de todos los sitios de Internet. Sin HTML, no hay página. Conocer lo básico ya te permite crear una landing de verdad.

Conceptos clave:

Las etiquetas vienen en pares: <h1>...</h1>. El contenido visible queda dentro de <body>. Empieza por el index.html.

Qué es:

CSS es el lenguaje de los estilos: colores, fuentes, tamaños, espaciados y posicionamiento. Es lo que transforma un HTML sin procesar en una página atractiva.

Por qué aprender:

Una landing debe atraer. El CSS es lo que marca la diferencia entre una página sin gracia y una página profesional y agradable a la vista.

Conceptos clave:

CSS selecciona un elemento (selector) y aplica reglas. Coloca los estilos en style.css y vincúlala al HTML con la etiqueta <link>.

Qué es:

El paso para enviar (push) tu landing a GitHub y activar Pages, para que el sitio quede accesible desde una dirección pública.

Por qué aprender:

Es el momento de estar "en línea": tu trabajo deja de ser un archivo en la computadora y se convierte en un sitio real que cualquiera puede visitar.

Conceptos clave:

Haz push con el index.html en la raíz, activa Pages y espera unos minutos. Cada nuevo push actualiza el sitio automáticamente.

Qué es:

Cambiar la dirección predeterminada usuario.github.io por un dominio propio que compras, como seunome.com.

Por qué aprender:

Un dominio propio transmite profesionalismo y es más fácil de compartir. Es un extra opcional, pero le da mucho valor al proyecto.

Conceptos clave:

Compra el dominio en un registrador, apunta el DNS a GitHub y configura el campo "Custom domain" en Pages. El HTTPS es gratis.

Qué es:

El ejercicio que cierra la ruta: crear, diseñar, versionar y publicar tu propia landing page, desde el primer comando hasta que el sitio esté en línea.

Por qué aprender:

Entregar un proyecto completo demuestra que dominas todo: terminal, Git, GitHub y Pages trabajando en conjunto.

Conceptos clave:

Une los 4 módulos en un solo flujo. Al final tendrás un enlace público para compartir y la base lista para la Trilha 2.
